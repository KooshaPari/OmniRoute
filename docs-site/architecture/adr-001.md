# ADR-001 — Canonical Routing

## Status

Accepted (fork governance hard-stop in effect as of 2026-09-01).

## Context

Multiple routing-related projects exist across the Phenotype org:

- **OmniRoute** (this repo) — fork of `diegosouzapw/OmniRoute`, an OpenAI-compatible AI gateway with routing, load balancing, retries, and fallbacks
- **phenoAI** — Phenotype AI agent workspace and tooling
- **phenoRouterMonitor** — LLM router with Prometheus monitoring + tracing
- **HeliosLab** — internal research gateway for routing experiments

The question: which one is canonical for production traffic?

## Decision

**OmniRoute is canonical** for OpenAI-compatible gateway traffic.

Rationale:

- Single-binary deploy
- SQLite default store (no external DB)
- Plugin manifest is mature and provider-agnostic
- `PerSpecDecision` hooks for governance interception
- Local-first: runs on Apple Silicon and Raspberry Pi

## Consequences

- `phenoAI` MUST route through OmniRoute for all OpenAI-compatible calls
- `phenoRouterMonitor` continues to be a Prometheus exporter — it MAY sit beside OmniRoute, but it MUST NOT replace it
- `HeliosLab` continues as a research branch; production traffic stays on OmniRoute
